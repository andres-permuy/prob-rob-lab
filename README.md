## What This Repository Provides

The repository currently contains the course ROS 2 packages and supporting files:

| Folder | Role |
|---|---|
| `models/` | Gazebo model assets packaged as `lab_gazebo_models`. |
| `prob_rob_labs/` | Main Python ROS 2 package used throughout the labs. Includes launch files, worlds, configuration, and course helper nodes. |
| `prob_rob_msgs/` | Custom ROS 2 message definitions used by the lab packages. |
| `vision/` | C++ vision package installed as `prob_rob_vision`. |
| `tools/` | Course setup scripts and development utilities supplied by the professor. |

The repository is intended to be edited directly as the course progresses. It is **not** a submodule of the professor's repository and should not contain a second nested checkout of `prob_rob_labs_ros_2`.

## Repository Layout

The repository must live directly under the workspace `src/` directory and must be locally named `prob_rob_labs_ros_2`:

```text
$MY_WORKSPACE/
├── build/                         # generated by colcon
├── install/                       # generated by colcon
├── log/                           # generated by colcon
└── src/
    └── prob_rob_labs_ros_2/       # THIS repository
        ├── .git/
        ├── README.md
        ├── LICENSE
        ├── models/
        ├── prob_rob_labs/
        ├── prob_rob_msgs/
        ├── tools/
        └── vision/
```

Do **not** create this structure:

```text
src/
└── prob_rob_labs_ros_2/
    └── prob_rob_labs_ros_2/       # WRONG: duplicate course checkout
```

A nested copy causes `colcon` to discover the same ROS packages twice and fail with a `Duplicate package names not supported` error.

## Required Workspace Layout

The professor's setup scripts define `MY_WORKSPACE` differently depending on the machine, but everything below `$MY_WORKSPACE` is identical.

| Environment | `$MY_WORKSPACE` |
|---|---|
| Personal Ubuntu 24.04 computer | `/home/<user>/ros2_ws` |
| Columbia lab Distrobox | `/run/host/workdir/<user>/ros2_ws` |

In both cases, this repository must therefore be cloned to:

```text
$MY_WORKSPACE/src/prob_rob_labs_ros_2
```

The GitHub repository itself may have a different name. The **local checkout name** should still be `prob_rob_labs_ros_2` so that every team member follows the same course layout.

## Requirements

The course environment uses:

- Ubuntu 24.04 (`noble`)
- ROS 2 Jazzy
- `colcon`
- CycloneDDS (`rmw_cyclonedds_cpp`)
- Gazebo / `ros_gz`
- TurtleBot3 simulation packages
- Additional ROS 2 packages installed by the professor's setup scripts

For a new machine, do not install these one at a time. Use the appropriate professor-provided setup script below.

> **Note:** `setup_home_workstation` performs system package installation and a full package upgrade. It may take a while on a fresh machine.

# Quick Start — Personal Ubuntu 24.04 Computer

Use this path for a personal laptop or desktop already running **Ubuntu 24.04**.

The commands below assume a fresh user who may not already have ROS installed.

### 1. Install Git

Git is needed once so the repository can be cloned before the course setup script is run.

```bash
sudo apt update
sudo apt install -y git
```

### 2. Create the course workspace

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
```

### 3. Clone this repository using the required local directory name

Copy this repository's Git URL from GitHub, then run:

```bash
git clone <THIS_REPOSITORY_URL> prob_rob_labs_ros_2
cd prob_rob_labs_ros_2
```

The result must be:

```text
~/ros2_ws/src/prob_rob_labs_ros_2
```

### 4. Run the professor's home-workstation setup

```bash
sudo ./tools/setup_home_workstation
```

Run the script with `sudo` as your normal user. Do **not** enter a root shell first.

The script installs ROS 2 Jazzy and the required course packages, configures CycloneDDS, creates the course environment variables and aliases in `~/.bashrc`, and sets:

```text
MY_WORKSPACE=/home/<user>/ros2_ws
```

### 5. Reload the shell environment and update rosdep

```bash
source ~/.bashrc
rosdep update
```

Verify that the workspace variable is correct:

```bash
echo "$MY_WORKSPACE"
```

Expected:

```text
/home/<user>/ros2_ws
```

### 6. Build the workspace

```bash
go_colcon
cc_prebuild
cc_build
source "$MY_WORKSPACE/install/setup.bash"
```

### 7. Verify the installation

```bash
ros2 pkg prefix prob_rob_labs
```

A successful setup should return a path under:

```text
/home/<user>/ros2_ws/install/prob_rob_labs
```

You are now ready to use the lab environment.

# Quick Start — Columbia Lab Computer

The Columbia machines use **Red Hat on the host** and run the course ROS environment inside an Ubuntu 24.04 Distrobox container.

Use the **local EE lab account assigned to you**, not your Columbia network account.

The course workspace must live on the lab work volume rather than in the local account's home directory. The provided setup script handles this automatically.

## A. One-Time Host Setup

### 1. Install Distrobox

On the lab computer host, run:

```bash
curl -s https://raw.githubusercontent.com/ihadzic/prob_rob_labs_ros_2/refs/heads/master/tools/install_distrobox | sh -s
```

Add the installed tools to your shell path:

```bash
echo 'export PATH=$PATH:~/.local/bin:.' >> ~/.bashrc
source ~/.bashrc
```

### 2. Create the course Ubuntu container

```bash
distrobox create \
  --name jazzy-e6911 \
  --image ubuntu:24.04 \
  --volume /workdir:/run/workdir \
  --hostname jazzy-e6911
```

Verify it exists:

```bash
distrobox list
```

## B. One-Time Container Setup

### 3. Enter the course container

```bash
distrobox enter jazzy-e6911
```

All ROS commands for the course must be run **inside this container** on the lab computer.

### 4. Download and run the professor's lab-workstation setup script

```bash
curl -fsSL \
  https://raw.githubusercontent.com/ihadzic/prob_rob_labs_ros_2/master/tools/setup_lab_workstation \
  -o setup_lab_workstation

chmod u+x setup_lab_workstation
sudo ./setup_lab_workstation
```

Then reload the shell configuration and update rosdep:

```bash
source ~/.bashrc
rosdep update
```

The script configures:

```text
MY_WORKSPACE=/run/host/workdir/<user>/ros2_ws
```

Verify it:

```bash
echo "$MY_WORKSPACE"
```

### 5. Clone the team repository into the required location

```bash
mkdir -p "$MY_WORKSPACE/src"
cd "$MY_WORKSPACE/src"

git clone <THIS_REPOSITORY_URL> prob_rob_labs_ros_2
```

If `$MY_WORKSPACE/src/prob_rob_labs_ros_2` already exists, **do not clone another copy beside or inside it**. Move/remove the old checkout first, then clone this repository into that exact path.

### 6. Build and verify

```bash
go_colcon
cc_prebuild
cc_build
source "$MY_WORKSPACE/install/setup.bash"

ros2 pkg prefix prob_rob_labs
```

A successful setup should return a path under:

```text
/run/host/workdir/<user>/ros2_ws/install/prob_rob_labs
```

From this point onward, open a terminal, enter the container, and work normally:

```bash
distrobox enter jazzy-e6911
```

The course `.bashrc` configuration will activate the ROS environment and the workspace overlay when it exists.

## Building the Workspace

The professor provides two aliases rather than using one generic build command.

### `cc_prebuild`

```bash
cc_prebuild
```

Equivalent to:

```bash
cd "$MY_WORKSPACE"
colcon build --packages-skip prob_rob_labs
```

This builds the supporting packages while skipping the main Python package.

### `cc_build`

```bash
cc_build
```

Equivalent to:

```bash
cd "$MY_WORKSPACE"
colcon build --symlink-install --packages-select prob_rob_labs
```

The symlink install allows existing Python files in `prob_rob_labs` to run directly from the source tree while they are being edited.

### Initial build

For a new workspace, always run both:

```bash
cc_prebuild
cc_build
source "$MY_WORKSPACE/install/setup.bash"
```

### Normal Python edits

Existing Python modules in `prob_rob_labs` are symlink-installed. Normal edits to those files generally do not require another build.

If you add a new Python module, change package metadata, or otherwise change what is installed by the package, run:

```bash
cc_build
source "$MY_WORKSPACE/install/setup.bash"
```

### Changes to supporting packages

If you change `prob_rob_msgs`, `prob_rob_vision`, `lab_gazebo_models`, or another package outside `prob_rob_labs`, rebuild the supporting packages first:

```bash
cc_prebuild
cc_build
source "$MY_WORKSPACE/install/setup.bash"
```

### Completely clean rebuild

If the build state becomes inconsistent:

```bash
cd "$MY_WORKSPACE"
rm -rf build install log
cc_prebuild
cc_build
source "$MY_WORKSPACE/install/setup.bash"
```

`build/`, `install/`, and `log/` are generated workspace directories and should not be committed to Git.

## Basic Usage

### ROS publish / subscribe smoke test

Terminal 1:

```bash
ros2 topic pub -r 10 /hello std_msgs/msg/String "{data: 'Hello World'}"
```

Terminal 2:

```bash
ros2 topic echo /hello
```

Stop both commands with `Ctrl+C` when finished.

### Launch the TurtleBot3 house simulation

```bash
ros2 launch turtlebot3_gazebo turtlebot3_house.launch.py
```

In another terminal, launch the steering GUI:

```bash
ros2 run rqt_robot_steering rqt_robot_steering --ros-args -p use_sim_time:=true
```

The entire steering command above is **one command**. Do not place a shell line break after `-p`.

### Launch the course empty-world simulation

```bash
ros2 launch prob_rob_labs turtlebot3_empty_launch.py
```

This is the course-provided empty-world launch used at the beginning of Lab 1.

## Git Collaboration

`origin` should point to the team's shared repository.

Check it with:

```bash
cd "$MY_WORKSPACE/src/prob_rob_labs_ros_2"
git remote -v
```

Before beginning work:

```bash
git pull
```

After making changes:

```bash
git status
git add <files>
git commit -m "Describe the change"
git push
```

For larger changes, use a feature/lab branch and merge through the team's normal review workflow.

### Do not commit generated workspace files

The following live outside this repository when the checkout is placed correctly, but they should never be committed:

```text
$MY_WORKSPACE/build/
```

### Do not add the professor repository as a nested clone

The course source is already part of this repository. Do not run this from inside the repo:

```bash
git clone https://github.com/ihadzic/prob_rob_labs_ros_2.git
```

That would create a second copy of every ROS package and break `colcon` package discovery.

## Updating From the Professor's Repository

The professor's repository is treated as the upstream course baseline:

```text
https://github.com/ihadzic/prob_rob_labs_ros_2
```

For most team members, **do not add or merge upstream independently**. Pull updates from the team repository normally so that everyone stays on the same baseline.

A maintainer who is responsible for bringing professor updates into the team repository can configure an `upstream` remote once:

```bash
cd "$MY_WORKSPACE/src/prob_rob_labs_ros_2"

git remote add upstream https://github.com/ihadzic/prob_rob_labs_ros_2.git
git fetch upstream
```

Check remotes:

```bash
git remote -v
```

Typical result:

```text
origin    <team repository>
upstream  https://github.com/ihadzic/prob_rob_labs_ros_2.git
```

When an upstream course update needs to be incorporated, review it before merging:

```bash
git fetch upstream
git log --oneline --decorate --graph HEAD..upstream/master
```

Then merge the update on the appropriate team branch and push it to `origin` so every team member receives the same version.

## Troubleshooting

### `Duplicate package names not supported`

Example:

```text
Duplicate package names not supported:
- prob_rob_labs:
  - src/prob_rob_labs_ros_2/prob_rob_labs
  - src/prob_rob_labs_ros_2/prob_rob_labs_ros_2/prob_rob_labs
```

There is almost certainly a second course repository nested inside this repository.

Check:

```bash
cd "$MY_WORKSPACE/src/prob_rob_labs_ros_2"
find . -mindepth 2 -name .git -print
```

Also inspect the tree:

```bash
tree -L 2
```

There should be only one checkout of the course packages.

---

### `Could not find ROS middleware implementation 'rmw_cyclonedds_cpp'`

The course environment expects CycloneDDS.

If the professor setup script completed successfully, this package should already be installed. Verify:

```bash
ros2 pkg prefix rmw_cyclonedds_cpp
```

If it is missing on an otherwise configured Ubuntu 24.04 / Jazzy machine:

```bash
sudo apt update
sudo apt install ros-jazzy-rmw-cyclonedds-cpp
```

Then open a fresh terminal or run:

```bash
source /opt/ros/jazzy/setup.bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
```

---

### Warnings reference an old workspace path

If `colcon` prints warnings about an old or deleted workspace in `AMENT_PREFIX_PATH`, `COLCON_PREFIX_PATH`, or `CMAKE_PREFIX_PATH`, open a clean terminal first.

If necessary, reset the current shell:

```bash
unset COLCON_PREFIX_PATH
unset AMENT_PREFIX_PATH
unset CMAKE_PREFIX_PATH
source /opt/ros/jazzy/setup.bash
```

Then source only the current workspace if it has already been built:

```bash
source "$MY_WORKSPACE/install/setup.bash"
```

Also remove any stale `source <old-workspace>/install/setup.bash` lines from `~/.bashrc`.

---

### `go_colcon`, `cc_build`, or `cc_prebuild` is not found

Reload the shell configuration written by the professor's setup script:

```bash
source ~/.bashrc
```

Then verify:

```bash
echo "$MY_WORKSPACE"
type go_colcon
type cc_build
type cc_prebuild
```

On the Columbia lab computer, make sure you are inside:

```bash
distrobox enter jazzy-e6911
```

---

### `ros2 pkg prefix prob_rob_labs` cannot find the package

Build and source the workspace:

```bash
go_colcon
cc_prebuild
cc_build
source "$MY_WORKSPACE/install/setup.bash"
```

Then retry:

```bash
ros2 pkg prefix prob_rob_labs
```

---

### `Couldn't parse trailing -p flag` from `rqt_robot_steering`

Run the full command on one line:

```bash
ros2 run rqt_robot_steering rqt_robot_steering --ros-args -p use_sim_time:=true
```

A line break after `-p` causes ROS to receive an incomplete parameter argument.
